# REPLのWeb検索と追質問に対応する対象

| ユーザーの「1回でweb検索は発動せず」という報告と `agent.enabled_tools`、および実モデルがtool choiceを無視した記録 | 外部の最新情報を求める入力で、モデルの任意判断に依存せず最初のLLM呼び出し前にagentが `web_search` を1回実行する | 最新・現在・今日・時点・ニュース・天気のいずれか、またはWeb・ウェブ・ネットと検索・調査を同時に明示した最新のuserメッセージ | 開始条件 | ユーザー入力 → agentがuserメッセージをqueryにした `web_search` を実行 → 検索結果を会話へ追加 | `requiresWebSearch` とは、最新のuserメッセージが外部の現在情報またはWeb検索を明示的に求め、かつ `web_search` が利用可能であることを指す | `requiresWebSearch` |
| `ai-agent` の実動作で `web_search` 後に「本文を取得しますか？」と停止した記録 | 検索結果だけで回答を終えず、同じターンでURLの本文を取得する | 成功した `web_search` の結果URLのうち、userメッセージに「公式」または `official` があればhost名とuserメッセージ中の英数字語が一致するURLを優先し、それ以外は検索順位が最上位のURLを `web_fetch` で1回取得する処理 | 事象 | `web_search` 成功 → URL選択 → agentが `web_fetch` を実行 → 本文を会話へ追加 → 回答生成 | `selectWebFetchURL` とは、検索結果URLから本文取得に使う1件を決める処理を指す | `selectWebFetchURL` |
| `internal/agent/loop.go` は同一ターン内でassistantのtool callとtool結果を保持するが、`internal/transport/cliui/repl.go` は最終assistant本文だけを次ターンへ残す | 「もう少し詳しく」で直前の検索結果と取得本文を再利用できるようにする | agent loopが当該ターンに追加したassistant tool call、tool結果、最終assistant回答の順序付きメッセージ列 | 記録 | 同一ターンのtool callとtool結果 → 最終回答 → 次のユーザー入力に渡す履歴 | `TurnMessages` とは、agent loopが1回の `Run` で入力履歴の後へ追加したメッセージだけを順序どおり複製した記録を指す | `TurnMessages` |
| ユーザーの「もう少し詳しく」で同じ回答を繰り返すという報告 | 追質問で直前回答だけでなく、その根拠となった検索結果と本文を参照させる | REPLが `EventFinal.TurnMessages` を次ターンの `agent.Input.Messages` に追加する処理 | 手段 | 前ターンの `TurnMessages` 保存 → 「もう少し詳しく」 → 保存済み本文を含む次のLLM呼び出し |  | `TurnMessages` の履歴追加 |
| 修正後の実動作でも「もう少し詳しく」に直前回答と同じ表を返した記録 | 追質問では既出回答を再掲せず、保存済み本文から新しい事実・説明・注意点を追加する | 最新のuserメッセージより前にassistant回答があり、最新のuserメッセージが「もう少し詳しく」「詳しく」「詳細」「more detail」「elaborate」「expand」のいずれかを含むこと | 開始条件 | 前ターンの回答と根拠保存 → 詳細を求める追質問 → 既出内容の反復を避けるsystem指示 → 追加説明 | `requiresExpandedAnswer` とは、直前までにassistant回答がある会話で、最新のuserメッセージが既出回答の追加説明を求めることを指す | `requiresExpandedAnswer` |
| 品質ゲートでGitleaksが未追跡の `models/` 約18GBを走査し続けた記録と、同ディレクトリをコミットしないというユーザー指定 | コミット対象外の巨大なGGUFをシークレット検査せず、実装と設定ファイルの検査を完了できるようにする | `.gitleaks.toml` のpath allowlistにあるリポジトリ直下の `models/` | 検査境界 | `gitleaks detect --no-git --source .` → `models/` を除外 → それ以外の作業ツリーを既存ルールで検査 | `models/ のGitleaks除外` とは、リポジトリ直下のローカルGGUF保存先だけを作業ツリー検査から外す設定を指す | `models/ のGitleaks除外` |
| PR前の差分確認で、agentが自動生成するtool call IDが全ターンで固定値だった記録 | 同じREPLで複数回Web検索しても、履歴内のassistant tool callとtool結果を一意に対応させる | 履歴中の同名tool call数を基にした9文字英数字のID。`web_search` は `webs`、`web_fetch` は `webf` と5桁の連番で構成する | 識別子 | 過去の同名tool call数を集計 → 次の連番を生成 → assistant tool callとtool結果の両方へ設定 | `nextAutomaticToolCallID` とは、会話履歴中の同名tool call数から次の9文字IDを生成する処理を指す | `nextAutomaticToolCallID` |
| 最終バイナリの実動作で軽い言い換え、導入句、system prompt断片、未完節、テンプレート断片が出力され、最大試行後には直前回答のバージョン番号だけを再掲した1項目が救済候補として返った記録 | モデルの指示追従や文字数だけに依存せず、追質問の画面出力から既出内容、同じ数字列、導入句、prompt断片、根拠外の文、テンプレート断片を除き、完結した本文を2項目以上返す | 詳細追質問で生成したassistant本文、直前のassistant本文、保存済み `web_fetch` tool結果。候補の数字だけを連結した列が直前回答の数字列に含まれる文を除外する。Web本文との対応を満たす完結文が2項目以上になるまで最大3回再生成し、未達候補は試行終了後も返さない。再生成は `背景`、`変更点`、`注意点` の3項目を各20文字以上で要求する | 事象 | 追質問の生成を画面へ即時送信せず保持 → 完結した文単位で既出文、同じ数字列、導入句、テンプレート断片を除外 → Web本文との対応と2項目以上を判定 → 不足なら最大3回再生成 → 合格候補だけを送信・保存し、未達なら生成失敗を明示 | `expandedAnswerContent` とは、詳細追質問の生成結果を完結した文単位で扱い、既出文、同じ数字列、導入句、テンプレート断片を除き、Web取得後は保存済み本文との対応も確認して、2項目以上を満たす候補だけを返す処理を指す | `expandedAnswerContent` |
