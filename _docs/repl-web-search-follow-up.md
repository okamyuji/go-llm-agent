# REPLで外部の最新情報を取得し、追質問へ根拠を引き継ぐ

対応表は `referent-table-repl-web-search-follow-up.md` に保存した。

## `ai-agent` で観測した検索実行と回答停止

`ai-agent` は `bin/agent chat` と `llm-agent-workspace/config.yaml` を使うaliasである。同じaliasを起動し、次の順で入力した。

1. `2026年8月10日時点のGo言語の最新安定版をWeb検索し、公式情報のURL付きで教えてください。`
2. `もう少し詳しく。`

最初の入力では `web_search` が1回実行されたが、`web_fetch` は実行されず、回答は `https://go.dev/doc/devel/release このサイトの最新安定版を確認し、本文を取得しますか？` で停止した。追質問では再び `web_search` が1回実行され、別のURLを示して同じ確認で停止した。

さらに新規プロセスで、AIニュース、東京の今日の天気、Go 1.25系の最新パッチリリースをそれぞれ尋ねた。3件とも最初の入力で `web_search` は実行されたが、`web_fetch` は実行されなかった。したがって、現在のモデルと強く時点を示す入力では「最初の入力で検索しない」を毎回は再現しなかった一方、検索から本文取得へ進まず、確認または検索結果だけで終わる動作は再現した。

## モデルの任意判断とREPLの履歴欠落が再現結果を生む

`llm-agent-workspace/config.yaml` は `agent.tool_choice` を指定していない。`internal/agent/loop.go` はこの場合に `ChatRequest.ToolChoice` を指定せず、ツールを呼ぶかどうかをモデルへ委ねる。system promptは検索と本文取得を指示しているが、実動作ではモデルがその指示に従わず、`web_search` 後に確認を返した。最初の検索実行もモデルの出力に依存するため、入力と生成結果によっては検索なしで回答できる。

同じターンの `internal/agent/loop.go` はassistantのtool callとtool結果を `msgs` に追加している。しかし `EventFinal` は最終assistant回答だけを返し、`internal/transport/cliui/repl.go` も画面へ出した最終assistant本文だけを `history` に追加する。このため、次の入力には直前の `web_search` 結果が渡らない。「もう少し詳しく」だけでは根拠を再利用できず、モデルは再検索または前回答と同じ確認を生成しやすい。

## 外部情報を求める入力ではagentが検索と本文取得を先に実行する

`web_search` が利用可能で、最新のuserメッセージが次のいずれかを満たすとき、agentは最初のLLM呼び出し前にuserメッセージ全体をqueryにした `web_search` を1回実行する。

- Web、ウェブ、ネットと検索・調査を同時に明示する。
- `最新`、`現在`、`今日`、`時点`、`ニュース`、`天気` のいずれかを含む。
- 英語で `search the web`、`browse`、`look up`、`latest`、`current`、`today`、`news`、`weather` のいずれかを含む。

`検索して`、`調べて`、`バージョン`、`リリース` だけでは開始しない。これらはローカルファイル検索や一般概念の質問でも使われるため、外部の現在情報を示す語またはWeb・ネットの明示を必要とする。

`web_search` が成功し、`web_fetch` が利用可能なら、検索結果からURLを1件選び、同じく最初のLLM呼び出し前に `web_fetch` を1回実行する。userメッセージに「公式」または `official` があれば、host名の区切り語とuserメッセージ中の英数字語が一致するURLを優先する。該当しない場合は検索順位が最上位のURLを使う。検索または本文取得が失敗しても自動再試行はせず、その結果をモデルへ渡して回答させる。

自動実行には既存の `executeOne` を使う。これにより、承認が必要な構成では承認を行い、ツール実行時間と成否を記録し、出力のリダクションと非信頼ラップを適用する。agentが生成するqueryとURL引数はJSONとして構築し、外部入力文字列をシェルへ渡さない。

この形は実モデルの差を吸収するために必要である。全ツールを広告したまま名前付きtool choiceで `web_fetch` を指定した実機試験では、モデルは指定を無視して検索結果の説明文を生成した。広告するツールを `web_fetch` だけに絞って `tool_choice=required` を指定した試験では直接URLを含む入力時には実行したが、検索結果を含む会話では再び説明文を生成した。したがって、tool choiceを検索→本文取得の完了保証には使わない。

Webツールは `agent.enabled_tools` への明示で既にopt-inされている。今回の指定はその範囲内で、外部情報を明示的に求める入力だけに適用する。通常の質問と、Webツールを無効化した構成は変更しない。

## 1回のagent実行で追加したメッセージを次のREPL入力へ残す

`EventFinal.TurnMessages` に、agent loopが入力履歴の後へ追加したassistant tool call、tool結果、最終assistant回答を順序どおり複製する。REPLは `TurnMessages` がある場合にその全件を `history` へ追加する。既存またはテスト用Serviceが `TurnMessages` を返さない場合は、従来どおり画面へ出した最終assistant本文を1件だけ追加する。

ツール結果を次ターンへ残すことで入力トークンは増えるが、直前に取得した本文を追質問で参照するために必要である。長い会話の縮約は既存の履歴管理の責務を維持し、この変更では新しい永続化や要約処理を導入しない。

自動実行するtool callのIDは、履歴中の同名tool call数から次の連番を生成する。`web_search` は `webs`、`web_fetch` は `webf` と5桁の連番を組み合わせ、Mistral-Nemo系の制約に合う9文字英数字を維持する。同じREPLで別の最新情報を検索しても、過去のtool call IDと重複させない。

## 詳細を求める追質問では既出内容以外を追加させる

前のassistant回答が履歴にあり、最新のuserメッセージが「もう少し詳しく」「詳しく」「詳細」「more detail」「elaborate」「expand」のいずれかを含む場合、そのターンのsystem promptへ次の制約を追加する。

- 直前の回答を再掲しない。
- 保存済みのtool結果を使い、まだ述べていない事実、理由、注意点、具体例を追加する。
- 追加できる情報がない場合は、同じ回答を繰り返さず不足を明示する。

この制約は当該ターンだけに適用し、REPL履歴へsystemメッセージとして保存しない。初回入力に「詳しく」が含まれるだけでは適用せず、前のassistant回答が存在することを開始条件にする。

実モデルはこのsystem指示があっても、既出のバージョン、URL、サポート期間、修正内容を箇条書きへ変えて再掲した。指示だけでは同じ生成を防げないため、詳細追質問では生成中のdeltaを画面へ即時送信せず、最終候補を保持する。候補を句点と改行で分割し、読点では分割しない。これにより「最新のものは…で」のような未完節を作らず、完結した文を評価する。Markdown記号、空白、句読点を除いた比較文字列が直前回答に含まれる文を除外する。完全包含でなくても、8文字以上の連続一致があるか、候補文の連続3文字の80%以上が直前回答に存在すれば、「2026年8月時点」と「2026年8月10日時点」のような軽い言い換えとして除外する。「以下の通り」「詳しく説明」「追加情報」「参考情報」だけの文も、事実を追加しない導入句として除外する。

Web取得後の追質問では、既出判定を通った文についても保存済み `web_fetch` tool結果との対応を確認する。正規化した候補文がtool結果と6文字以上連続一致するか、候補文の連続3文字の30%以上がtool結果に存在する文だけを回答候補にする。さらに、大文字とunderscoreからなる3文字以上の識別子の直後に `=` がある文をテンプレート断片として除外する。これにより、実機で観測した「人称・敬語」「使用する言語」などsystem prompt由来の文と `.RELEASE=MONTH_DAY` を追加情報として受理しない。Web取得を伴わない会話ではtool結果との根拠判定だけを行わない。

候補文の数字だけを連結した列が直前回答の数字列に含まれる場合も、バージョン番号などの再掲として除外する。未提示部分が2項目以上なら、その部分だけを追加情報として画面へ送り、REPL履歴にも同じ本文を保存する。長い1項目だけでは合格にしない。本文量が不足する場合はtool hopを消費せず、当該LLMリクエストの複製内で最新userメッセージへ制約を追記し、生成を最大3回やり直す。新しいsystemメッセージを会話末尾へ置かない。再生成では保存済み `web_fetch` 結果にある事実を `背景`、`変更点`、`注意点` の3項目として各20文字以上生成し、既出の固有名詞、数値、URLを出さない形式を要求する。この追記はREPL履歴へ保存しない。最後まで2項目を満たさない候補は返さない。すべての候補が導入句、既出内容、同じ数字列、テンプレート断片、または根拠外の文だけなら、非信頼のtool本文をagentが直接転載せず、追加情報を生成できなかったことを明示する。

## コミット対象外のローカルGGUFをGitleaksから除外する

品質ゲートの `gitleaks detect --no-git --source .` は未追跡ファイルも検査するため、コミット対象外の `models/` にある約18GBのGGUFを走査し続けた。この変更では `.gitleaks.toml` のpath allowlistへリポジトリ直下の `models/` だけを追加する。既存の除外である `.env.example`、`.env`、`config.yaml` は維持し、その他の作業ツリーには既存のデフォルトルールを適用する。

この除外はユーザーがコミットしないと指定したローカルモデル保存先に限定する。実装、設定、文書、fixtureの検査範囲は変更せず、Gitleaks自体を無効化しない。

## コマンドで確認できる完了条件

1. agent loopのテストで、外部の最新情報を求める入力では最初のLLM呼び出し前に `web_search` が1回実行され、`web_fetch` が利用可能で検索が成功した場合は `web_fetch` も1回実行され、そのtool callとtool結果がLLM入力に含まれる。
2. 通常の質問、`web_search` がない構成、検索失敗では不要なWebツール実行を行わない。
3. REPLの2回目の `agent.Input.Messages` に、1回目のassistant tool call、tool結果、最終assistant回答が順序どおり含まれる。
4. 同じ履歴でWeb検索を2回実行したとき、各ターンの `web_search` と `web_fetch` のtool call IDが重複せず、すべて9文字英数字である。
5. 実際の `ai-agent` で最初の入力中に `web_search` と `web_fetch` が実行され、本文取得の確認で停止せず回答する。
6. 同じREPLで `もう少し詳しく。` と入力したとき、既出内容または導入句だけの生成候補は画面へ送られず、本文を伴う未提示情報だけ、または追加情報を生成できない旨が返る。
7. `models/` を走査対象から除いたうえで、`rtk bash scripts/quality-gate.sh` と `rtk env RUN_E2E=1 bash scripts/quality-gate.sh` が終了コード0で `all quality checks passed` を出す。
